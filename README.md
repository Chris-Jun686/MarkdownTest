### 构建原则：按照“并发峰值”定规模

此次PE与LQA编辑人员数目 **“单个项目在最短交付窗口内，单个语种需要同时上线多少人”** 来进行测算。

### 考虑变量

**单项目单语种的文本量（字数/字符数）**

根据过往Nomori, 绯月杀以及Song of Kings项目，字数约在10000-15000字左右。

**PE编辑人员的日均产能**

一名熟练的自由译者日均处理量通常在 **2,500–4,000词** 左右，具体取决于文本复杂度、CAT工具效率和术语库完善程度。因此，如果项目要求48小时内交付，那么单语种至少需要：

> **单语种PE需求人数 = 总字数 ÷ （2,500 × 可用工作日数）**

**LQA测试人员的并行需求**

LQA需要实际进游戏逐条验证，效率受限于游戏可玩性、bug复现难度和版本稳定性。对于目前承接的项目大小，单语种 **1–2名LQA测试人员** 是一个合理的起步配置。

### 初期Pool大小

结合以上变量，初期的**pool基准**可以考虑：

| 角色 | 单语种Pool建议 | 说明 |
|---|---|---|
| **PE编辑** | **2-3人** | 目前阶段确保至少2人可同时处理一个项目，并确保余出1人紧急储备 |
| **LQA测试人员** | **2人** | 覆盖一个项目的并行测试需求，同时预留额外需求空间 |
| **合计/语种** | **4-5人** | 三语种种子池合计约 **12–15人** |

如果同时承接两个项目，可根据需要将池子按比例扩大到1.5–2倍，或在人才获取渠道中获取可快速加入项目的候选人。

## 📡 人才获取渠道：分层获取，按语种差异化

### 🏗️ 通用分层结构

**Tier1：核心层（长期稳定合作）**

核心层包含**反复合作、质量可控、响应及时**的自由译者或小型团队，通常以 **转介和定向挖掘** 为主：
- 从现有合作过的译者中筛选表现优异者，主动邀请进入种子池
- 通过发行商或同行LSP的推荐获取可信人选
- 在游戏本地化行业会议（如LocWorld、GDC）的社交场合建立直接联系

行业最佳实践明确指出，应**从推荐、会议和经过策展的平台中拉取候选人，而非开放网络目录**，因为后者未经验证且过时很快。

**第二层：弹性层（可快速激活的候选人，5–10人/语种/角色）**

这一层用于应对项目高峰和种子层不可用的情况。获取渠道包括：
- **ProZ.com**：全球最大的自由译者社区，有专门的游戏本地化招聘板块，经常有日语、韩语、俄语的游戏本地化岗位发布。ProZ还提供了 **PortaRecruit** 平台，专门用于多语言游戏本地化招聘，支持从测试到签约的全流程管理。
- **51找翻译**：国内语言服务平台，有大量日语、韩语、俄语的游戏本地化兼职岗位，适合获取中文→目标语言方向的自由译者。
- **TranslatorsCafe**：腾讯ILC等大厂在此发布游戏本地化自由译者招募，涵盖翻译、校对和LQA。

**第三层：储备层（长期观察对象，数量不限）**

通过社群、论坛和内容平台持续观察潜在候选人，不急于合作，但保持联系。这一层的价值在于**当种子层和弹性层都出现缺口时，有一个已经“预热”过的候选人池可以调用**。

### 🎯 按语种的渠道侧重

**日语**
- **专业社群**：Steam社区中的“日本語化作業者互助会”（TransModders）和“日本語化情報”群组聚集了大量日化爱好者和从业者，部分成员具备商业本地化能力，适合挖掘种子层候选人。
- **平台**：ProZ.com上日语相关的游戏本地化岗位发布频繁，PortaRecruit平台也有日语Narrative Designer和Linguist的持续招聘。
- **注意**：日本自由译者对长期合作的稳定性要求较高，建议以“持续提供项目”而非“单次项目”为切入点沟通。

**韩语**
- **平台**：ProZ.com上有中→韩、韩→日等方向的游戏本地化自由译者招募，Keywords Studios等LSP也在持续扩充韩语人才库。
- **社群**：韩国的“Hangul Patch”社区生态中，存在少量持续活跃的团队，部分成员具备从粉丝翻译转向商业翻译的潜力，但需要经过严格的测试和培训。
- **注意**：韩语游戏本地化市场相对集中，头部LSP（如Keywords、TransPerfect）占据了大量优质自由译者资源，初创团队需要通过**更灵活的合作条款**（如更快的付款周期、更清晰的术语支持）来建立吸引力。

**俄语**
- **平台**：ProZ.com是俄语游戏本地化自由译者最集中的平台之一，PortaRecruit平台在俄语方向的招聘中明确标注“合格候选人在签约后即可分配项目任务”，说明俄语人才的可获得性较高。
- **价格参考**：俄语游戏本地化自由译者的时薪通常在 **$25–$30 USD** 区间，在初创团队的预算范围内具有较好的性价比。
- **注意**：俄语译者对术语一致性和风格指南的依赖度较高，在测试阶段应重点考察其**在无完整术语库条件下的判断能力**。


## 🔄 从“招募”到“维护”：让资源池活起来

### 🗂️ 建立结构化的资源档案

每个进入种子层和弹性层的候选人，都应记录以下信息，并集中管理（建议使用Notion、Airtable或专门的Vendor Management工具）：

| 字段 | 说明 |
|---|---|
| 语种/角色 | 日语PE / 韩语LQA / 俄语PE+LQA等 |
| 合作状态 | 活跃 / 待激活 / 观察中 / 已退出 |
| 质量评分 | 基于过往项目的PE编辑率、LQA bug发现率等 |
| 可用性 | 当前负载、预计可接单时间 |
| 费率 | 词价或时薪，便于快速报价 |
| NDA/MSA状态 | 是否已签署保密协议和主服务协议 |

行业最佳实践强调，应将资源池作为**一份活的记录**来维护，有明确的负责人、定期审查和单一可信来源，而不是一次性文档。

### 📊 用指标驱动维护，而非凭感觉

资源池的核心管理指标应围绕 **质量、效率、成本** 三个维度：

- **PE编辑率**：MT输出经过PE编辑后，被修改的比例。编辑率过高说明MT质量或术语库需要优化，也可能说明该译者的PE风格过于激进。
- **LQA bug发现率**：每千字或每轮测试中发现的本地化问题数量。过低可能意味着测试不够深入，过高则可能说明PE阶段遗留问题较多。
- **准时交付率**：这是初创团队对发行商承诺的生命线。
- **返工率**：交付后被发行商或内部审核退回修改的比例。

建议**每季度做一次资源池Review**，淘汰连续两个项目质量不达标的成员，同时从储备层中激活表现积极的候选人。

### 🛡️ 风险分散：不要依赖单点

对每个语种、每个角色，确保 **至少2人处于“随时可激活”状态**。如果某个语种的种子层只有1人，而这个人在项目期间因故无法工作，整个语种的交付就会面临风险。资源池的**冗余度**比**规模**更重要。


## 💎 总结

对于初创团队，日语、韩语、俄语资源池的构建，**建议从每个语种7–11人的种子池起步**（PE编辑4–6人 + LQA测试人员3–5人），通过转介和ProZ.com等策展平台获取种子层候选人，用分层档案和季度Review机制维护活性。资源池的质量不在于人数，而在于 **“需要的时候，能快速拉起一支经过验证的团队”**。随着承接项目类型的稳定和发行商关系的加深，再逐步扩大弹性层和储备层的覆盖范围。
