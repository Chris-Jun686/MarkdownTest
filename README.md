# Unreal Engine Localization

**Prepared for Dev · August 2026**

这篇文档旨在帮助开发团队了解虚幻引擎（UE）的本地化系统，规范与Orbit8团队对接的完整工作流程。涵盖了如何导出需要本地化的文本、交付的文件格式、如何导入翻译文本以及最终的校验方法。

---

## 什么是虚幻引擎的本地化系统？

虚幻引擎的本地化系统是一个内置的多语言翻译框架，无需下载第三方软件。它使用FText来存储所有面向用户且可翻译的文本。在运行时，引擎会根据玩家的语言设置自动切换文本，无需修改任何代码。需要注意的是：普通字符串（FString）不会被本地化，必须使用FText。

---

## 可本地化的文本格式

### C++: NSLOCTEXT 宏

```cpp
NSLOCTEXT("UI_MainMenu", "Btn_Start", "开始游戏");
NSLOCTEXT("Item_Weapon", "Sword_Name", "铁剑");
```

### 蓝图: Text 类型变量

引擎会自动收集蓝图中的Text类型变量及其默认文本内容。

## 本地化资产保存路径与文件含义

本地化文件保存在项目的 `Content/Localization/<目标名称>/` 目录下：

#### TABLE 1 — 本地化文件类型说明

| 文件类型 | 说明 |
|---------|------|
| manifest | 文本清单（记录所有需要翻译的文本ID及来源文件路径） |
| .locmeta | 本地化元数据（记录各语言间的关联信息） |
| .archive | 源文本库（内部存储未翻译的原始文本） |
| .po文件 | 交付给Orbit8团队进行翻译的明文文件 |
| .locres文件 | 编译后的二进制资源文件（仅供打包运行时使用，不可编辑） |

> **IMPORTANT** — 交接重点：交付给Orbit8团队的文件只能是.po格式，绝对不能交付.archiv或.locres文件，否则Orbit8将无法正常读取和回传。

## 如何导出需要本地化的文本

1. 打开顶部菜单栏：**工具 → 本地化控制板（Localization Dashboard）**。
2. 选择配置搜索范围：
   - C++收集：选择"从文本文件收集"，搜索目录填写源码所在文件夹；
   - 蓝图收集：选择"从包收集"，包含路径通配符填写内容浏览器目录；
3. 点击**收集文本**；
4. 收集完成后，在目标语种（如zh-Hans）所在行，点击右侧的"**导出此语言的翻译**"，引擎将自动生成.po格式的翻译文件；
5. 将生成的.po文件交付给Orbit8团队进行翻译和校对。

## 如何导入翻译后的文本文件

### 文件放置要求

确保Orbit8返回的.po文件命名规范（如Game.po），并放置在对应的语言目录下（如 `Content/Localization/Game/zh-Hans/Game.po`），不要随意修改文件名或路径。

### 执行导入

在 **工具 → 本地化控制板** 中，不要在顶部的"导入文本"按钮操作（该按钮仅用于导入内部.archives文件）。

> **IMPORTANT** — 正确做法：在语言列表中找到目标语种（zh-Hans）那一行，点击右侧的"**导入此语言的翻译**"，选择翻译后的.po文件即可。

### 编译文本

导入完成后，务必点击"**编译文本**"，以生成.locres二进制文件，随后才能在游戏运行时调用。

## 预期效果（如何验证）

在 **编辑 → 编辑器偏好设置 → 区域和语言 → 预览游戏语言（Preview Game Language）** 中，切换需要显示的语言种（如zh-Hans），即可在编辑器中实时预览本地化完成的内容。

## 常见问题排查（FAQ）

### Q1：点击"收集文本"时，未能收集到任何内容？

- **原因分析：** 收集路径（搜索目录/包含路径通配符）填写错误，或不包含任何可收集文本内容；或者是"项目设置 → 本地化"中的目标（Target）没有正确配置。
- **解决办法：** 仔细检查收集路径，确保路径包含源码或蓝图文件；同时回到"项目设置 → 本地化"确认目标已注册。

### Q2：导入翻译文件时，窗口提示未能找到.po文件，或者导入后没有任何反应？

- **原因分析：** 误点了控制板最上方的"导入文本"按钮（该按钮只用于导入.archives文件，不读取外部.po）。
- **解决办法：** 必须选择目标语种那一行右侧的"**导入此语言的翻译**"按钮来进行导入。

### Q3：导入翻译文本后，切换预览语言仍然显示未翻译（显示英文或Key值）？

**原因分析：**

1. 导入后未点击"编译文本"；
2. .po文件内部标头的语言代码与UE配置不符（如.po文件里写的是zh_CN，而UE配置为zh-Hans）；
3. 引擎本地化缓存未刷新。

**解决办法：**

1. 重新在本地化控制板中点击"编译文本"；
2. 联系Orbit8检查.po文件头部Language：字段是否与UE完全一致；
3. 保存项目后，退出并重新打开虚幻引擎。

### Q4：我们交付给Orbit8的文件，为什么对方反馈无法打开或无法翻译？

- **原因分析：** 开发团队可能误将内部的.archives或.locres文件发给了Orbit8团队。
- **解决办法：** 重新导出，只交付.po文件。这是与Orbit8唯一的标准化交接格式。
